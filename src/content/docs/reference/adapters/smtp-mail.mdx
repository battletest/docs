Your own mail server. Notification content — including finding titles — never reaches a third-party email vendor.

This provider fills the **mail** slot. Configure it in
**Settings → Providers**, or during first-run setup.

## Settings

| Key | Field | Type | Required | Notes |
|---|---|---|---|---|
| `host` | SMTP host | text | Yes | — |
| `port` | Port | number | No | 587 for STARTTLS, 465 for implicit TLS, 25 for an internal relay that does not authenticate. Default: `587`. |
| `secure` | Implicit TLS | yes / no | No | Defaults from the port: on for 465, STARTTLS otherwise. |
| `user` | Username | text | No | Leave empty for an internal relay that accepts unauthenticated mail from this host. |
| `pass` | Password | secret reference | No | — |
| `from` | From address | text | Yes | Must be an address your relay will accept as a sender, or everything is rejected after the connection succeeds. |
| `testRecipient` | Send the test message to | text | No | Only used when you press Test. Nothing is sent here otherwise. |

<Note>
  One field is a secret (`pass`). Secrets are never stored in the database — you give a reference and the value is resolved when it is used. `env:NAME` reads a process environment variable; `file:/run/secrets/name` reads a mounted secret file.
</Note>

## What the connection test checks

Saving runs a live test against the credentials you supplied. Every check below is evaluated against the real service, not inferred from the configuration.

| Check | Outcome |
|---|---|
| Relay reachable and TLS negotiated | Must pass |
| Credentials accepted | Must pass |
| Test message accepted for delivery | Must pass |

---
title: Authorise testing targets
description: Declare organisation scope and approve public hosts.
---

## Declare scope

Open **Settings → Policy → Testing scope** and select the organisation. You need permission to manage its testing scope.

1. Select **Add entry**.
2. Choose **Domain** or **Network range**.
3. Enter a domain or CIDR range and record a note if needed.
4. Save the entry.

A domain entry covers that domain and its subdomains. A CIDR entry covers IP addresses inside that range.

## Approve a public host

A public hostname inside declared scope also requires a host approval.

1. Select **Authorise host** in the public host approvals section.
2. Enter the exact hostname, explain the authorisation, and select its validity period.
3. Save the approval.

Approving `example.com` does not approve `www.example.com`. Approve each public hostname to be tested. The account, justification, and approval date are recorded. Revoke an approval to withdraw it.

## Internal targets and DNS verification

Private IP addresses and recognised internal domain names, such as `service.corp.internal`, can run when included in declared scope. Ordinary public-style hostnames are treated as public by this check, even if your DNS points them at an internal address.

A target with active DNS verification can run through the DNS verification path without a scope entry or host approval. Follow [Add a target](/docs/how-to/adding-a-target) to publish its verification record. Declaring scope does not create a DNS verification record.
